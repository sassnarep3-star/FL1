Validation gates

A gate set is the difference between a leaderboard and a lottery. Hard gates cannot be overridden by profit: a strategy that made money while failing a hard gate is evidence of variance, not skill. Thresholds below are our proposed rules (a design decision), whereas every statistical method cited is from the literature register. All are implemented in engine/gates.py, which turns a bet log into this table, filled in.

Order of operations: G-12 first (may we run it at all), then G-9 and G-3 (is the evaluation honest), then G-1, G-2, G-5, G-6 (is it distinguishable from luck), then G-7, G-8, G-10, G-4 (does it survive reality), then G-11 and G-13 (does it keep working, and is the ranking gameable).

A strategy that passes everything is still only 'not refuted'. Nothing in this gate set proves an edge; it only removes the ways a false one gets promoted. That distinction is the reason the leaderboard ranks confidence bounds rather than returns.

Where a gate is currently unevaluable (G-3 and G-7 depend on data we do not have), the correct status is 'blocked', not 'passed'. The site shows it that way.

Verification rule. Every factual row links to an official source — the league (nfl.com and its subdomains), a state gaming regulator, or a peer-reviewed publication. A value that could not be confirmed from an official source is left blank and flagged rather than estimated. Source verification levels: FETCHED = page opened and read · INDEX-MEANS = seen through a search index of the official document only · LINKED = reached from an official page, not opened · UNREACHABLE = tried and failed.
